## 1. 产品维度

### 1.1 核心价值主张 ★★★★☆

> *"打开手机，GPS 自动定位，3 秒内看到附近有空位的停车场——不再绕圈找车位。"*

| 要素 | 评分 | 说明 |
|------|------|------|
| 问题真实性 | ⭐⭐⭐⭐⭐ | 新加坡司机平均花 10-20 分钟找车位，CBD 高峰期更严重 |
| 解决方案有效性 | ⭐⭐⭐⭐ | GPS → 推荐 → 空位率预测，流程简洁高效 |
| 差异化程度 | ⭐⭐⭐⭐ | 专注 HDB 停车场 + ML 预测 + 天气因子，与竞品差异明显 |
| 用户粘性 | ⭐⭐⭐ | 收藏 + 登录是仅有的留资手段，缺乏推送、历史记录等 |

### 1.2 用户体验分析

**优势**：
- 🟢 零学习成本 — 打开即看，GPS 自动定位
- 🟢 地图 + 列表双视图，信息密度合理
- 🟢 GREEN/YELLOW/RED 三色状态直观易懂
- 🟢 3 小时趋势预测为决策提供依据

**劣势**：
- 🔴 纯 SPA 无 SSR，SEO 完全不可见（Google 搜不到）
- 🔴 无移动端适配 — 司机最核心的使用场景是**开车时看手机**
- 🟡 前端 UI 较基础，缺乏视觉精致感（与 Carousell/Parkopedia 差距明显）
- 🟡 无导航集成 — 选好停车场后需手动切到 Google Maps
- 🟡 无语音播报 — 驾驶场景下安全性不足

### 1.3 功能完整度

| 功能模块 | 状态 | 评价 |
|----------|------|------|
| GPS 附近搜索 | ✅ | 核心功能，体验良好 |
| 实时空位 | ✅ | 依赖 ETL 30 分钟刷新 |
| 停车场详情 + 历史 | ✅ | 24h 历史数据完善 |
| 地址搜索 | ✅ | ILIKE 模糊匹配 |
| 用户注册/登录 | ✅ | JWT，基础功能 |
| 收藏夹 | ✅ | 已登录用户可用 |
| ML 预测 | ✅ | LightGBM + k-NN 代理 |
| 导航跳转 | ❌ | 缺失 — 高优先级 |
| 推送通知 | ❌ | 缺失 — 差异化功能 |
| 费率信息 | ❌ | 缺失 — HDB 费率各不相同 |
| 无障碍车位 | ❌ | 缺失 |
| 充电桩信息 | ❌ | 缺失 — EV 快速增长 |

## 2. 技术维度

### 2.1 架构评分 ★★★★☆

```
┌─────────────────────────────────────────────────┐
│                   ParkGuideSG                    │
├──────────┬──────────┬──────────┬────────────────┤
│ Frontend │ Backend  │   ML     │   Data         │
│ React    │ FastAPI  │ LightGBM │ PostgreSQL     │
│ Vite     │ psycopg2 │ k-NN     │ PostGIS-ready  │
│ Leaflet  │ Pydantic │ LLM降级  │ Haversine SQL  │
└──────────┴──────────┴──────────┴────────────────┘
         │          │          │          │
         ▼          ▼          ▼          ▼
     Render.com  ──────────────────────  GitHub Actions
     (PaaS)      Single Docker Container  (ETL every 30min)
```

| 维度 | 评分 | 评价 |
|------|------|------|
| 架构清晰度 | ⭐⭐⭐⭐⭐ | 前后端分离，服务层明确，模型独立 |
| 可扩展性 | ⭐⭐⭐ | sync DB 连接是瓶颈，改用 asyncpg pool 可提升 3-5x |
| 可靠性 | ⭐⭐⭐⭐ | 三级推理降级（ML→LLM→Heuristic），不依赖单一模型 |
| 数据质量 | ⭐⭐⭐⭐ | Data.gov.sg + NEA 官方数据源，ETL 完整 |
| 安全性 | ⭐⭐⭐ | JWT 存 localStorage（XSS 风险），密码无复杂度要求 |

### 2.2 技术债务清单

| 优先级 | 问题 | 影响 | 修复成本 |
|--------|------|------|----------|
| 🔴 P0 | 所有路由使用 sync psycopg2（非 async） | FastAPI 的 async 优势完全浪费，并发能力差 | 中 |
| 🔴 P0 | JWT 存 localStorage | XSS 攻击可窃取 token | 低（改用 httpOnly cookie） |
| 🟡 P1 | 每个路由独立创建 DB 连接 | 无连接池，高并发下性能差 | 中 |
| 🟡 P1 | 前端无测试 | 重构风险高 | 中 |
| 🟡 P1 | Render 单容器部署 | 无水平扩展能力 | 高 |
| 🟢 P2 | ETL 30 分钟间隔 | 高峰期数据不够实时 | 低（改 cron） |
| 🟢 P2 | 无 CI/CD 测试步骤 | 代码质量无法自动验证 | 中 |
| 🟢 P2 | 无 API 版本控制 | 接口变更会影响前端 | 低 |

### 2.3 ML 模型评估

**亮点**：
- LightGBM 选择正确 — 表格数据 + 时间序列场景下表现优异
- k-NN 空间代理处理非 EPS 停车场（数据缺失问题）— 聪明的工程决策
- LLM 降级作为中间层 — 比纯 heuristic 有更好的泛化能力
- 特征工程合理（hour, day_of_week, is_weekend, is_holiday, weather）

**不足**：
- 单模型无 ensemble — 无法评估不确定性
- 无 A/B 测试框架 — 模型更新无法渐进发布
- 无模型性能监控 — 不知道线上预测准确率是否退化
- 仅使用 3 个月训练数据 — 无法捕捉季节性模式（学校假期、节日购物季）

## 3. 团队与流程维度

### 3.1 团队效能

根据 Iteration 1 数据：

| 指标 | 数值 | 行业基准 | 评价 |
|------|------|----------|------|
| 团队规模 | 3 人 | 3-5 人（MVP） | 偏小 |
| 迭代周期 | 20 工作日 | 10-14 天 | 偏长 |
| 计划 Velocity | 50% | 60-70% | 合理偏低 |
| 实际 Velocity | **28%** | 40-60% | ⚠️ 偏低 |
| 完成故事数 | 5 个 | 5-8 个 | 正常 |

**Velocity 偏低的原因推测**：
1. 3 人团队承担全栈（前端 + 后端 + ML + DevOps）— 上下文切换成本高
2. 28% 的实际 velocity 说明有大量计划外工作（基础设施搭 建、工具链调试、数据管道）
3. Iteration 1 通常是最慢的（领域学习 + 技术选型）

## 5. 商业前景维度

### 5.1 市场规模

| 指标 | 估算 |
|------|------|
| 新加坡私家车保有量 | ~650,000 辆 |
| 每日出行车辆 | ~1,000,000 次 |
| 每次找车位平均耗时 | 10-20 分钟 |
| 每年因找车位浪费时间 | ~60,000,000 小时 |
| **可寻址市场（新加坡）** | **~$50M/年**（时间价值 × 时薪） |

### 5.2 商业化路径

| 模式 | 可行性 | ARPU 潜力 | 时间线 |
|------|--------|-----------|--------|
| **免费 + 广告** | ⭐⭐⭐ | $1-3/用户/年 | 近期（6个月） |
| **Premium 订阅**（实时推送、历史趋势、无广告） | ⭐⭐⭐⭐ | $20-50/用户/年 | 中期（12个月） |
| **B2B API 授权**（物流公司、租车公司） | ⭐⭐⭐⭐ | $500-5000/客户/月 | 中期（12个月） |
| **政府合作**（LTA/URA 数据整合） | ⭐⭐ | 项目制 $50-200K | 长期（18个月） |
| **停车场运营优化**（为 HDB/商场提供 occupancy 分析） | ⭐⭐⭐ | $1-5K/停车场/年 | 长期（18个月） |

### 5.3 商业模式健康度

```
免费用户 → 广告收入（低）
    ↓ 转化 3-5%
付费用户 → 订阅收入（中高）
    ↓
B2B 客户 → API/SaaS 收入（高）
```

**核心问题**：当前完全免费，没有收入模型。需要在 Iteration 2/3 开始设计变现路径。

## 7. 优先级行动建议

## 附录：一句话总结

> **ParkGuideSG 是一个技术底子扎实、产品方向正确、但急需补齐移动端体验和安全短板的停车场推荐系统。真正的竞争壁垒不在于 ML 模型本身，而在于持续积累的时空数据和先发优势。建议 Iteration 2 聚焦「安全修复 + 移动体验 + 导航闭环」，Iteration 3 启动「订阅变现 + B2B API」。**
